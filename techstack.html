Architecture

大数据六层技术架构

自下而上，逐层递进。每一层解决一类问题，共同支撑数据的价值转化。

① 数据采集层FlumeSqoopPython 采集
② 数据存储层HDFSHBaseHive关系型数据库
③ 资源管理层YARN资源调度
④ 计算处理层MapReduceSparkHive
⑤ 分析挖掘层Spark SQL数据仓库数据挖掘
⑥ 可视化应用层数据可视化统计报表图表展示
专业视角：数据自下而上流动——底层解决「存得住、算得动」，上层解决「看得懂、用得上」。
Ecosystem 01

Hadoop 生态核心组件

Hadoop 是大数据的基石，其生态以 HDFS + YARN + MapReduce 为核心，向外扩展出完整的工具链。

H

HDFS

分布式文件系统。将大文件切块（Block）多副本存储在多台机器上，实现高容错、高吞吐的存储。

NameNodeDataNode副本机制
Y

YARN

资源管理与调度框架。把集群的 CPU、内存统一管理，按需分配给各个计算任务。

ResourceManagerNodeManager
M

MapReduce

分布式计算模型。将任务拆分为 Map（映射）与 Reduce（归约）两阶段，在集群中并行执行。

分而治之并行计算
Hv

Hive

基于 Hadoop 的数据仓库工具。用类似 SQL 的 HQL 查询 HDFS 上的数据，降低使用门槛。

数据仓库SQL 化
Hb

HBase

面向列的分布式 NoSQL 数据库，适合海量数据的随机实时读写。

列式存储实时读写
S

Flume / Sqoop

数据搬运工具：Flume 采集日志流，Sqoop 在关系型数据库与 HDFS 之间批量传输数据。

采集导入导出
Ecosystem 02

Spark 生态核心模块

Spark 基于内存计算，速度可达 MapReduce 的数十倍，是当前主流的统一计算引擎。

SC

Spark Core

核心引擎，基于 RDD 弹性分布式数据集实现内存计算与容错。

SQ

Spark SQL

结构化数据处理，支持用 SQL 与 DataFrame 查询海量数据。

SS

Spark Streaming

流式计算，把实时数据流切成小批次进行处理，实现准实时分析。

MapReduce 词频统计思想

分而治之的经典模型
wordcount · 逻辑示意
// Map 阶段：把每行文本拆成 <单词, 1>
map(line):
  for word in line.split():
    emit(word, 1)

// Reduce 阶段：对相同 key 的计数求和
reduce(key, values):
  return (key, sum(values))

Hadoop 与 Spark 对比

维度MapReduceSpark
计算方式磁盘为主内存为主
中间结果落盘 HDFS缓存在内存
速度较慢快数十倍
迭代计算不擅长擅长
实时处理不擅长支持（Streaming）
适用场景大规模离线批处理批处理 + 迭代 + 流处理
